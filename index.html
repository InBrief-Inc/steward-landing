Steward is a local-first desktop app for software engineering: requirements, architecture, code explanation, API research, debugging, tests, review and documentation.

How it works Project status

Four task actions. Only Implement changes code.

Each task runs under an explicit action, separate from the model you choose. Discuss, Plan and Review never write to your source.

  • Discuss

    Work through code, requirements and architecture questions. Source stays read-only.

  • Plan

    Turn a request into steps and acceptance criteria before anything changes.

  • Implement

    Edit code in a folder you attach, run the checks you approve, then get an independent source review. Turn it on in Settings first.

  • Review

    Check code and GitHub pull requests against your own architecture. Source stays read-only.

Your data stays on your machine.

Working data lives in a local database. Personal use needs no Steward account, hosted API, PostgreSQL, Redis or Docker.

  • Local storage

    Projects, conversations, memory, reference files, history, approvals and usage live in SQLite in your OS application-data folder.

  • Keys in the OS keychain

    Provider keys stay in macOS Keychain, Windows Credential Manager or Linux Secret Service. Backups never include them.

  • Approvals you choose

    Ask for approval, approve for me, or full access after a native confirmation. Publishing to GitHub needs approval of the exact text. Approvals expire and work once.

  • Memory you control

    Conflicting statements and model suggestions wait in Memory for your approval or dismissal. Pin, disable, edit or delete any fact.

  • Your model, your limits

    Use your own OpenRouter account, and optionally your installed Codex or Claude Code CLI. Set fast and best models and per-task and rolling 30-day spending limits.

  • Explicit GitHub access

    Steward reads only the repositories you allow. Publishing a review still needs your approval.

Pre-release, and clear about what is missing.

Built with Tauri 2, React, TypeScript and a Rust runtime. Signed installers and update testing are part of the V1 release gate.

  • Working now

    • Local planning and routing across your configured models
    • Persistent memory, backups and usage tracking
    • Eight built-in engineering procedures
    • GitHub review with approvals, and optional Tavily web search

  • Not yet

    • Live provider and tool acceptance testing
    • Signed installers, notarization and tested updates
    • Cloud sync, accounts, shared workspaces, hosted billing and server telemetry are later capabilities
